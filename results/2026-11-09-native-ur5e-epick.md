Landmine: Isaac Lab 3.0 builds no PhysX scene-query structure unless `SimulationCfg(enable_scene_query_support=True)`, and PhysxCfg's field of the same name is overwritten by the SimulationCfg one (isaaclab_physx/physics/physx_manager.py:853-854). Without it every raycast finds nothing, the surface gripper's included: the gripper sat in Closing for its whole 1 s retry at stand-offs of 0, 1 and 4 mm, and an omni.physx raycast_closest probe from the cup returned hit False. With it the same probe hits each dish at 1.05 to 1.07 mm. The old robot scripts never needed scene queries (no other script in code/ makes one).
Also found: the asset starts at its authored zero pose, not at init_state (0.19 rad off HOME_Q 0.5 s after reset in run 2), so the script teleports to HOME_Q before calibrating. /ur5e/joints/robot_gripper_joint, a fixed joint from wrist_3_link to nothing, draws a PhysX "disjointed body transforms" warning and changed nothing measurable.
GPU loss: run 1 died at boot with torch's "No CUDA GPUs are available", and nvidia-smi in the container printed "Failed to initialize NVML: Unknown Error". `docker inspect --format '{{json .State.Health}}' dishsim-isaac` gave {"Status":"unhealthy","FailingStreak":5716,...} with empty outputs; that check only greps the newest Kit log for "App is loaded.", so it reads unhealthy whenever no Kit app runs. One `docker restart dishsim-isaac` brought the GPU back.
Runs: five. Run 1 was the container. Runs 2 to 4 attached nothing (run 2 the first code, run 3 added the stand-off ladder and the raycast probe, run 4 set the flag on PhysxCfg, where it is ignored). Run 5 passed.
